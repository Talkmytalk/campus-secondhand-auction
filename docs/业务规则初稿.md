# 校园二手拍卖系统：业务规则初稿

编制日期：2026 年 10 月 19 日  
文档状态：主要方向已由组长确认，其余采用第一版默认规则。对应后端已实现并通过自动测试；前端页面与小组联调尚未完成。

## 已确认的方向

- 前端技术暂不清楚，先采用通用 HTTP / JSON 接口开展后端设计。
- 第一版采用公开加价、固定时间截止、最高有效出价者获胜的流程。
- 需要页面模拟付款，不实际扣钱，不接入真实支付服务。
- 使用用户名和密码注册、登录，不对接学校账号。
- 第一版不做商品图片，只先跑通发布和出价流程。
- 只做到模拟付款成功，不增加卖家交付、买家确认收货。

其余细节采用下文的第一版默认规则，后续可以根据组内反馈调整。

## 一、建议采用的拍卖流程

卖家发布闲置物品，设置起拍价、最低加价金额和截止时间。其他用户公开出价，系统显示当前最高价。截止后，最高有效出价者获得购买资格；没有有效出价则为流拍。

同一个用户可以发布物品，也可以参与他人拍卖。第一版建议每场拍卖对应一件物品，发布后立即开始，采用固定截止时间。

## 二、第一版范围建议

实现范围为用户注册登录、发布拍卖、拍卖列表和详情、提交出价、查看出价记录、查询拍卖结果、查询本人相关订单和模拟付款。

已确认需要模拟付款：获胜者在页面点击模拟付款，后端校验身份和订单状态后记录付款成功，不实际扣款。第一版不增加交付与确认收货流程。

用户自行注册用户名和密码，不验证真实校园身份。第一版不做管理员审核。出价接口从登录令牌获取出价者，不能任由前端填写其他人的用户编号。

## 三、建议的出价规则

| 编号 | 规则 | 示例或说明 |
| --- | --- | --- |
| B01 | 只有身份有效的用户可以提交出价 | 使用用户名密码登录后取得的有效令牌 |
| B02 | 卖家不能对自己发布的物品出价 | 防止卖家自行抬价 |
| B03 | 只能对存在且正在进行的拍卖出价 | 拍卖不存在或已结束时拒绝 |
| B04 | 首次出价必须大于或等于起拍价 | 起拍价 20 元，首次出价 20 元有效 |
| B05 | 后续出价必须大于或等于当前最高价加最低加价金额 | 当前 20 元，最低加价 2 元，则下一次至少 22 元 |
| B06 | 不要求出价为加价金额的整数倍 | 在上例中，23 元也有效；第一版默认规则 |
| B07 | 采用服务端时间判断截止；到达截止时刻即拒绝出价 | 服务端时间大于或等于截止时间时不能出价 |
| B08 | 金额必须为正数且最多两位小数 | 拒绝零、负数及超过两位小数的金额；当前接口技术上限为 9999999999.99 元 |
| B09 | 同价出价不算有效的新出价 | 依照 B05 判断，不随机决定赢家 |
| B10 | 多人同时出价时，必须根据最新已接受的价格重新校验 | 已采用数据库行锁和事务，不让两个请求都基于旧价格成功 |
| B11 | 已接受的出价记录不可直接修改或删除 | 第一版建议不支持撤回出价 |
| B12 | 拍卖结束后不得继续更新价格和赢家 | 结束结果需在并发情况下保持一致 |

最低加价金额必须大于零。第一版默认允许当前最高出价者继续提高自己的价格，但不允许卖家出价。

## 四、发布与结束规则建议

- 物品标题、描述、起拍价、最低加价金额和截止时间为必填项；第一版没有图片上传。
- 起拍价必须大于零，截止时间必须晚于发布时的服务端时间。
- 第一版建议发布后禁止修改起拍价、最低加价金额和截止时间，避免影响参与者。
- 第一版建议不支持发布后撤销拍卖；后续若需要取消功能，应另行规定有出价时的处理方式。
- 截止时有有效出价：最高有效出价者获胜，成交金额为该有效出价的金额。
- 截止时没有有效出价：流拍，不产生买家和成交金额。
- 获胜表示取得购买资格；线下交付是否完成应作为另一项状态，不与拍卖结束混用。

## 五、待跟进事项

1. 前端使用的技术、已有页面和运行方式。
2. 前端与后端是否在同一台电脑上运行，以及最终演示方式。
3. 第一版默认不做物品分类、搜索、管理员审核、修改与撤拍；如要增加，应另行排期。
4. 目前不限制拍卖的最短与最长时长，只要求截止时间晚于服务端当前时间。
5. 第一版默认不做付款期限和自动取消，也不自动顺延给第二名。

## 六、模拟付款规则建议

1. 拍卖进行中不能付款；流拍不生成付款订单。
2. 一场成功结束的拍卖只产生一笔成交订单，买家是获胜者，卖家是发布者。
3. 订单金额取拍卖结束时的最高有效出价，由后端确定，不能由前端修改。
4. 只有订单买家可以执行模拟付款，其他用户执行时必须拒绝。
5. 订单从“待模拟付款”变为“已模拟付款”，记录付款时间。
6. 同一订单重复提交付款时，返回原有成功结果，不重复创建订单、不重复记录付款。
7. 页面和接口返回均应明确标注“模拟付款”，不声称完成了真实转账。
8. 已确认第一版不增加交付与收货状态。
