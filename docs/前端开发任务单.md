# 前端开发任务单：校园二手拍卖第一版

交接日期：2026 年 10 月 23 日。先阅读《队员交接说明》，启动本机后端，再阅读《接口说明》与《业务规则初稿》。前端技术由前端成员结合自身经验选择，并向组长反馈页面启动地址。

## 一、要完成哪些页面或功能区域

页面可以组合，重点是能够走完整条业务流程。

| 页面或区域 | 最少需要完成的内容 | 对应接口 |
| --- | --- | --- |
| 注册、登录与退出 | 用户名密码输入、错误提示、保存登录令牌、显示当前账号、退出 | /api/auth/register、login、me、logout |
| 拍卖列表 | 标题、起拍价或当前最高价、状态、截止时间；点击进入详情；分页 | GET /api/auctions |
| 发布拍卖 | 标题、描述、起拍价、最低加价金额、截止时间；显示发布结果 | POST /api/auctions |
| 拍卖详情与出价 | 商品说明、最高价、最低可出价、截止状态、出价输入、出价记录与错误提示 | GET /api/auctions/{id}、GET/POST /api/auctions/{id}/bids |
| 我的订单与模拟付款 | 展示买入和卖出的订单、身份、金额与付款状态；只有买家看到待付款操作 | GET /api/orders/mine、GET /api/orders/{id}、POST /api/orders/{id}/simulate-payment |

暂不开发图片上传、管理后台、搜索分类、撤拍、聊天、真实支付和收货流程；有新的需求先与组长确认范围。

## 二、接口连接要求

- 默认后端地址为 `http://127.0.0.1:8080`，建议把它放在一个统一的配置位置，方便以后修改。
- 发送 JSON 时使用 `Content-Type: application/json`；需要登录的接口带 `Authorization: Bearer <实际token>`。
- 注册成功后还需要调用登录接口取得令牌。用户编号以登录或当前用户接口返回为准。
- 返回结果没有统一的 `data` 外层：列表内容在 `items` 中，详情字段直接位于返回对象中。不要自行假设返回格式。
- 检查 HTTP 状态；失败时显示后端返回的 `message`。遇到 401 时提示重新登录。
- 用户身份由后端从令牌判断；发布、出价和付款不需要上传卖家编号、出价者编号或买家编号。
- 测试截止时间由页面根据用户选择动态生成，并带上时区；不要把文档里的示例日期写死在代码中。

## 三、最容易做错的地方

1. 没有人出价时，`currentHighestPrice` 为 null，应显示“暂无出价／起拍价”，不能显示成已经有人按起拍价出价。
2. 进行中拍卖的最低可出价以 `nextMinimumPrice` 为准。出价成功或提示价格过低后，重新查询详情和出价记录。
3. 卖家不能给自己出价。页面可以隐藏或禁用按钮，后端仍会独立检查。
4. 页面显示倒计时，后端判断最终截止。状态为 `SOLD` 或 `UNSOLD` 时禁用出价；请求途中到期也要能显示后端错误。
5. 第一版没有实时推送，可以每隔几秒刷新详情；切换页面后停止对应刷新。
6. 订单列表同时包含买入和卖出。只有当前用户等于 `buyerId` 且状态为 `PENDING_PAYMENT` 时才展示付款操作。
7. 模拟付款接口不需要提交金额。收到成功响应后，再更新订单状态，页面明确写“模拟付款，不实际扣钱”。
8. 用户输入的标题、描述和用户名按普通文本显示；接口返回的 UTC 时间转为本地时间显示。

## 四、第一轮验收流程

1. 在页面注册并登录 A，发布起拍价 20 元、最低加价 2 元、几分钟后结束的物品。
2. 退出 A，登录 B，查看物品并出价 20 元，页面更新最高价和出价记录。
3. B 再出 21 元时显示拒绝原因，出 22 元时成功；用 A 出价时拒绝。
4. 拍卖到期后显示成交结果，不能继续出价；B 在本人订单中完成模拟付款。
5. 刷新页面并重新查询后，订单仍为已模拟付款。

如果某个接口无法满足页面需要，记录页面场景、请求和响应，先与组长核对。

- 主要页面截图或一段完整流程演示。
