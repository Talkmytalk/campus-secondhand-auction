# 校园二手拍卖系统：接口说明

版本：第一版。具体运行与测试结果见《测试记录》。

## 一、前端先看这里

本机接口地址：`http://127.0.0.1:8080`。前端技术不限，使用 HTTP 请求交换 JSON 数据即可。

请求带 JSON 时设置 `Content-Type: application/json`。登录后，需要登录的接口额外设置：

```text
Authorization: Bearer 登录接口返回的token
```

发布者、出价者和付款者身份都取自登录令牌，不需要在请求中传入用户编号。令牌默认有效 24 小时，退出后失效。

所有时间使用带时区的 ISO 8601 格式。例如北京时间 2026 年 10 月 25 日 20:00 可以写成 `2026-10-25T20:00:00+08:00`，也可以写成 `2026-10-25T12:00:00Z`，二者是同一时刻。接口返回 UTC 时间，页面需要转为本地时间显示。

金额单位为元，最多两位小数；请求可以使用字符串，例如 `"22.00"`。当前技术上限为 `9999999999.99` 元。页面应将返回的标题、描述和用户名作为普通文本显示。

分页统一使用 `page`（从 0 开始）和 `size`（1—100，默认 20），返回：

```json
{"items": [], "page": 0, "size": 20, "totalElements": 0, "totalPages": 0}
```

## 二、接口总览

| 方法 | 路径 | 是否登录 | 用途 |
| --- | --- | --- | --- |
| GET | /api/health | 否 | 确认后端是否启动 |
| POST | /api/auth/register | 否 | 注册 |
| POST | /api/auth/login | 否 | 登录，取得令牌 |
| GET | /api/auth/me | 是 | 查看当前用户 |
| POST | /api/auth/logout | 是 | 退出，使该令牌失效 |
| POST | /api/auctions | 是 | 发布拍卖 |
| GET | /api/auctions?page=0&size=20 | 否 | 拍卖列表，按编号从新到旧 |
| GET | /api/auctions/{id} | 否 | 拍卖详情 |
| POST | /api/auctions/{id}/bids | 是 | 提交出价 |
| GET | /api/auctions/{id}/bids?page=0&size=20 | 否 | 出价记录，最新在前 |
| GET | /api/orders/mine?page=0&size=20 | 是 | 与我有关的订单，包含卖出与买入 |
| GET | /api/orders/{id} | 是 | 订单详情，仅买卖双方可看 |
| POST | /api/orders/{id}/simulate-payment | 是 | 仅买家可执行模拟付款 |

## 三、注册和登录

注册与登录的请求体相同：

```json
{"username": "student_a", "password": "Password123"}
```

第一版约定：用户名为 3—32 位字母、数字或下划线，区分大小写；密码为 8—64 位不含空格的英文可见字符。注册重复用户名返回 409。密码加密摘要保存在数据库，接口不返回密码或摘要。

注册成功返回 HTTP 201：

```json
{"id": 1, "username": "student_a"}
```

登录成功返回 HTTP 200（令牌示意值不可直接使用）：

```json
{
  "token": "登录生成的随机令牌",
  "tokenType": "Bearer",
  "expiresAt": "2026-10-20T10:00:00Z",
  "user": {"id": 1, "username": "student_a"}
}
```

`GET /api/auth/me` 返回当前用户编号和用户名。退出成功为 HTTP 204，无响应体；退出只影响本次令牌，其他设备已登录的令牌仍独立有效。

## 四、发布拍卖

`POST /api/auctions`：

```json
{
  "title": "二手台灯",
  "description": "功能正常，可在校内交付",
  "startingPrice": "20.00",
  "minimumIncrement": "2.00",
  "endsAt": "2026-10-25T20:00:00+08:00"
}
```

标题不为空且最多 100 字符，描述不为空且最多 2000 字符。起拍价和最低加价都大于零。截止时间必须晚于服务端当前时间。演示时可以设置几分钟后结束，不需要等到示例日期。

发布成功为 HTTP 201，返回拍卖详情。发布后立即开始；第一版没有修改、删除、撤拍和提前结束接口。

## 五、拍卖详情和出价

详情返回示例：

```json
{
  "id": 1,
  "sellerId": 1,
  "title": "二手台灯",
  "description": "功能正常，可在校内交付",
  "startingPrice": 20.00,
  "minimumIncrement": 2.00,
  "currentHighestPrice": null,
  "nextMinimumPrice": 20.00,
  "highestBidderId": null,
  "status": "RUNNING",
  "createdAt": "2026-10-19T10:00:00Z",
  "endsAt": "2026-10-25T12:00:00Z"
}
```

没有有效出价时，`currentHighestPrice` 和 `highestBidderId` 为 null，不代表已有用户按起拍价出价。

`POST /api/auctions/1/bids`：

```json
{"amount": "20.00"}
```

成功为 HTTP 201：

```json
{"id": 1, "auctionId": 1, "bidderId": 2, "amount": 20.00, "createdAt": "2026-10-19T10:01:00Z"}
```

第一次出价至少为起拍价；以后至少为当前最高价加最低加价金额。最低加价为 2 元时，20 元之后可以出 22 元，也可以出 23 元。卖家不能自己出价；最高出价者可以继续提高出价。

多人同时出价时，后端使用数据库行锁串行校验最新价格。若两个请求同时在无人出价的拍卖中出 20 元，只允许一个成功；另一个必须刷新后重新出价。

拍卖状态：

| status | 含义 | 页面行为建议 |
| --- | --- | --- |
| RUNNING | 进行中 | 展示最低可出价，符合身份条件时可提交 |
| SOLD | 已结束且有获胜者 | 禁用出价，引导获胜者查看订单 |
| UNSOLD | 已结束且无人出价，流拍 | 禁用出价，不展示付款入口 |

结束后 `nextMinimumPrice` 为 null。服务端时间到达截止时刻即拒绝出价，不依赖页面倒计时或后台任务是否已经执行。后台每秒批量结算一次，查询详情、列表或本人订单时也会按需结算。

建议前端在出价成功后重新获取详情；收到价格过低或拍卖已结束错误时也刷新详情。第一版不含 WebSocket 推送，页面可以每隔几秒刷新当前价格。

## 六、订单与模拟付款

到期有有效出价才产生订单，一场拍卖最多一笔。订单只对买卖双方可见。

订单示例：

```json
{
  "id": 1,
  "auctionId": 1,
  "sellerId": 1,
  "buyerId": 2,
  "amount": 20.00,
  "status": "PENDING_PAYMENT",
  "createdAt": "2026-10-25T12:00:01Z",
  "paidAt": null,
  "simulated": true
}
```

`POST /api/orders/1/simulate-payment` 不需要请求体，不接收付款金额；后端以订单金额为准。

成功返回 HTTP 200 和订单详情，状态变为 `PAID`，并带有 `paidAt`。重复请求返回同一订单和原来的付款时间。其他人或卖家执行付款返回 403。页面必须显示“模拟付款，不实际扣款”。

第一版不做付款超时取消、不顺延给第二名、不做卖家交付和买家收货状态。

## 七、错误处理

错误响应示例：

```json
{"code": "BID_TOO_LOW", "message": "本次出价至少为 22.00 元", "timestamp": "2026-10-19T10:02:00Z"}
```

| HTTP 状态 | 常见 code | 含义 |
| --- | --- | --- |
| 400 | VALIDATION_ERROR / INVALID_AMOUNT / INVALID_DEADLINE | 输入不合法 |
| 400 | SELF_BID / BID_TOO_LOW / AUCTION_ENDED | 出价不符合规则 |
| 401 | LOGIN_REQUIRED / INVALID_CREDENTIALS | 未登录、令牌失效或账号密码错误 |
| 403 | BUYER_ONLY / ORDER_FORBIDDEN | 没有权限 |
| 404 | AUCTION_NOT_FOUND / ORDER_NOT_FOUND / NOT_FOUND | 资源或接口不存在 |
| 409 | USERNAME_EXISTS / DATA_CONFLICT / BUSY_RETRY | 数据冲突或需要重试 |

页面应检查 HTTP 状态，并显示 `message`，不要把 HTTP 请求发送成功等同于业务操作成功。

## 八、前后端连接时需要核对

本机默认允许的前端来源为 `localhost` / `127.0.0.1` 的 5173、3000 端口。其他来源需在 `auction.allowed-origins` 中明确增加。

默认后端只监听本机地址。若前端同学在另一台电脑上连接，需要另行配置监听地址、前端实际来源和本机网络访问；第一版尚未进行跨电脑联调。不必为了页面开发直接把服务部署到公网。

参考：[Spring Boot 官方系统要求](https://docs.spring.io/spring-boot/3.5/system-requirements.html)、[官方 Maven 插件说明](https://docs.spring.io/spring-boot/3.5/maven-plugin/getting-started.html)。项目的实际版本以 `backend/pom.xml` 为准。
