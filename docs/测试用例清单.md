# 校园二手拍卖系统：测试用例清单

用途：供测试同学安排人工测试和接口测试。此表是预期行为，不代表测试同学已经执行。后端自动测试的实际结果见《测试记录》。

准备三个账号：A 为卖家，B、C 为竞拍者。测试拍卖建议设为几分钟后结束，避免等待过长。

| 编号 | 操作或条件 | 预期结果 |
| --- | --- | --- |
| T01 | 使用合规用户名与密码注册 | 成功，返回用户编号与用户名，不返回密码 |
| T02 | 再次注册同名用户 | 拒绝，提示用户名已存在 |
| T03 | 用户名过短、密码过短或过长 | 拒绝，不产生账号 |
| T04 | 使用错误密码登录 | 拒绝，不能取得有效令牌 |
| T05 | 正常登录、查看当前用户 | 当前身份与所登录账号一致 |
| T06 | 不登录发布商品或提交出价 | 拒绝，要求登录 |
| T07 | 退出后使用原令牌操作 | 拒绝，原令牌失效 |
| T08 | 使用已到期令牌操作 | 拒绝，要求重新登录 |
| T09 | A 发布合法商品 | 发布成功，状态进行中，无最高出价者 |
| T10 | 截止时间是过去或当前时刻 | 拒绝发布 |
| T11 | 标题或描述为空，或金额非正数 | 拒绝发布 |
| T12 | B 首次出价等于起拍价 | 成功 |
| T13 | B 首次出价低于起拍价 | 拒绝，不产生出价记录 |
| T14 | 最高价 20 元，加价 2 元，C 出 22 元 | 成功 |
| T15 | 同上，C 出 21.99 元或重复出 20 元 | 拒绝，最高价及出价记录不变 |
| T16 | 同上，C 出 23 元 | 成功，不要求为加价金额的整数倍 |
| T17 | A 对自己发布的商品出价 | 拒绝 |
| T18 | 出价为负数、零、超过两位小数或无法解析 | 拒绝 |
| T19 | 前端伪造卖家编号或出价者编号 | 身份仍以令牌为准，不能冒充他人 |
| T20 | B、C 同时对无人出价的拍卖出起拍价 | 只有一个成功，另一人须刷新并提高出价 |
| T21 | 到达截止时刻后继续出价 | 拒绝，不依赖页面倒计时是否结束 |
| T22 | 有人出价的拍卖到期 | 确定最高有效出价者，只产生一笔订单 |
| T23 | 无人出价的拍卖到期 | 流拍，不产生订单 |
| T24 | 多次结算、反复查询同一已结束拍卖 | 结果不变，不重复产生订单 |
| T25 | 非买卖双方查看订单 | 拒绝 |
| T26 | 卖家或非获胜者进行模拟付款 | 拒绝 |
| T27 | 获胜者进行模拟付款 | 状态变为已模拟付款，记录付款时间 |
| T28 | 修改付款请求中的金额或买家编号 | 不影响后端保存的成交金额和买家身份 |
| T29 | 重复或同时点击同一订单的模拟付款 | 同一订单处理一次，重复请求返回原有结果 |
| T30 | 拍卖列表、详情和出价记录分页 | 正常返回；非法页码或过大的分页大小被拒绝 |
| T31 | 关闭并重启后端 | 已提交的账号、拍卖、出价与付款记录仍存在 |
| T32 | 页面连接后端 | 登录令牌正常携带，错误消息能显示，时间显示正确 |
| T33 | 页面执行付款 | 始终标明模拟付款，不实际扣钱 |

测试同学实际执行时，应另加“执行日期、实际结果、通过／失败、截图或响应记录、问题编号”等列。前端页面相关用例必须在页面完成后执行，不能用后端自动测试替代。
