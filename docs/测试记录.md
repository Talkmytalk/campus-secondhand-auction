## 二、打包与真实 HTTP 检查

已成功生成可运行的 Spring Boot JAR。使用该 JAR 启动本机 18080 端口服务，通过真实 HTTP 请求完成以下检查，全部通过：

1. 注册三个独立账号并登录，核对身份。
2. 卖家发布中文标题商品，核对返回的中文内容。
3. 接受 20 元有效首价，拒绝 21.99 元不足加价，接受另一用户 22 元出价，拒绝卖家出价。
4. 等到真实截止时间，确认状态为已成交、赢家正确，并拒绝继续出价。
5. 只生成一笔 22 元订单，拒绝卖家付款，接受获胜者模拟付款；重复付款保持原付款时间。
6. 立即强制结束该测试程序，再使用同一数据库启动，确认账号令牌、赢家、两条有效出价记录和已模拟付款订单仍然存在，付款时间不变。

该检查使用单独的文件数据库。测试程序在验证后已停止，不占用后续演示端口，也未在默认演示数据库中预置账号。

## 三、验证中发现并修正的问题

- 依赖下载源连接失败或超时：使用项目级官方仓库配置，保留缓存重试，最终完成构建。
- Windows Java 本地连接初始化失败：将本地套接字临时目录设为当前工作目录后通过验证；相关测试参数已写入项目，应用运行时的处理办法见 README。
- 模拟付款后立即强制结束进程时，文件数据库的延迟写入可能导致最后状态未落盘：为本地文件数据库配置 `WRITE_DELAY=0`，重新验证后通过。
- 付款时间在数据库保存时的精度差异：将付款时间统一到数据库的微秒精度，并增加带小数秒的回归验证。
