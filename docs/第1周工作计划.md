# 校园二手拍卖系统：第 1 周工作计划

编制日期：2026 年 10 月 19 日  
计划提交日期：2026 年 10 月 26 日（周一）  
文档状态：初稿，供小组讨论；下列计划不代表已经完成。

## 一、已经确认的信息

- 小组三人：组长兼后端开发一人、前端开发一人、测试一人。
- 组长负责后端代码、业务逻辑制定、出价规则校验、接口编写。
- 老师未指定编程语言、框架和数据库。
- 每周提交个人工作周报、小组工作周报、个人工作成果。
- 此前完成情况尚未核实，不能据此声称已完成任何代码或测试。

## 二、本周拟完成的目标

先确认需求和接口，再争取跑通“发布拍卖 → 查看拍卖 → 提交出价 → 查询结果 → 获胜者模拟付款”的最小流程。

当前后端采用 Java 17、Spring Boot、Maven 和 H2 本地文件数据库。组长使用 IDEA；已检查本机 Java 和 Maven。构建与测试的最终结果另见《测试记录》。

已确认公开加价、到期最高有效出价者获胜、用户名密码注册登录、不做图片、只做到模拟付款成功。前端技术和实际联调方式尚待确认。若时间不足，优先完成可验证的核心接口，并在周报中明确尚未完成的功能。

## 三、建议分工（待组内确认）

| 成员 | 建议任务 | 可交付成果 |
| --- | --- | --- |
| 组长／后端 | 确认需求，制定业务规则，编写数据结构与接口，处理出价校验，汇总进度 | 业务规则文档、接口说明、后端代码、运行说明 |
| 前端同学 | 确认页面和技术，开发拍卖列表、详情与出价操作，连接后端接口 | 页面代码、运行说明、演示截图 |

测试同学可先根据规则准备测试用例，无须等全部代码完成。涉及组员进度的周报内容应由本人确认。
